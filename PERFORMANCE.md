`plugin.iter_strings(context)` retains full record decoding by default. Native batches preserve source order, every structural field address, repeat scope, schema and structure hash, table ID, text and codec provenance. A decode error is reported after all preceding strings have been delivered; iteration never resumes past a bad record. Python validates batch JSON with Pydantic and checks both source owners even while yielding buffered values. Closing the generator releases its cursor without freeing either borrowed owner.

For extraction-only workloads, `plugin.iter_strings(context, validate_nontext=False)` skips record types only when the schema proves that they cannot contain translatable values. Unknown record schemas, custom decoders, unresolved references and depth-limit uncertainty remain on the conservative decoding path. This option does not validate skipped payloads: use the default mode or the explicit record-validation API when those errors matter. No filtering option changes which strings are considered translatable.

This distinction is observable in real inputs: with mixed decoding enabled, the installed Serana Dialogue Add-On emitted the same 11,331 references through both paths, but all-record decoding subsequently rejected a text-free `SCEN` expression while extraction-only traversal reached EOF. These modes are therefore not interchangeable when error equivalence matters. Performance comparisons requiring identical decoding must use the strict default on both sides. Decoding every record is not a substitute for running the separate semantic validation API and reviewing its diagnostics.

Each batch processes at most 128 records from Python, stopping after a record when 4096 string values or 2 MiB of uncompressed source payload have accumulated. An individual record can exceed these soft limits. The cursor stores traversal positions rather than a list of every record or string. Complete record decoding is still required for string-bearing records so that editing addresses retain their full structural guards.

## Mixed encodings

Use `SemanticContext.for_plugin(package, plugin, mixed=True)` to opt into per-string UTF-8 preference with a detected legacy fallback. If the plugin-level prior is UTF-8 or ASCII, the legacy fallback is Windows-1252. If the detector selects a legacy codec such as Windows-1251, that codec becomes the fallback. Whole strings are checked; bytes from different strings are never combined to decide that one string is valid UTF-8. Selected field codecs are retained by the editor, including within repeated structures.

This is explicitly a heuristic, not universal encoding detection. Some byte sequences have valid but different interpretations in multiple codecs. A supplied `.cpoverride` remains authoritative and disables the mixed heuristic. Use field-specific codec selection when the intended interpretation is known. The mixed tests cover UTF-8/Windows-1252 and UTF-8/Windows-1251 siblings, repeated message buttons, read/edit/reload round trips, unchanged sibling bytes and override precedence.

## Stage-level optimization

The next local pass adds an opt-in native `profile-string-stages` build feature and reversible local Python instrumentation. Normal builds have no stage timers or profiling JSON extension. The measurements separate record decoding, complete structural hashing, string projection, decoded-value destruction, native-call time, owned JSON copying/freeing, Pydantic wire validation, reference construction, SSE-AT resolution and verification fingerprinting. Native-call time not accounted for by completed record stages includes traversal, JSON serialization/allocation/destruction and failed batches; it must not be called serialization-only time. Native record-lookup timing is nested inside SSE-AT resolution, not an additional independent cost. The encoding-decision factory can likewise be measured within context construction, but includes runtime construction rather than bare detector execution.

The measured hot path repeatedly scanned all callback bindings for every decoded scalar and array element. An immutable exact-path callback index now preserves declaration order and binding identity, including multiple slots at the same path, while avoiding those scans. Actual normalizers, callbacks, selector decisions and errors are unchanged. The index is initialized lazily, shared by registry clones and does not cache callback results.

## Reproduce

Select the native DLL or shared object with `BETHKIT_LIB`. Use the same schema, files, codec policy and machine for both runs, and avoid other CPU-heavy jobs. `--legacy` explicitly uses the original per-record snapshot projection as an oracle. Use the published 0.8.0 library without `--mixed` for the original baseline, or the development library to isolate batch overhead from parser changes. Reports are created exclusively, so choose a new output path for each run.

```sh
uv run python scripts/benchmark_strings.py --data /path/to/Data --plugins /path/to/plugins.txt --legacy --output build/perf/reference.jsonl
uv run python scripts/benchmark_strings.py --data /path/to/Data --plugins /path/to/plugins.txt --output build/perf/batched.jsonl
uv run python scripts/compare_string_benchmarks.py build/perf/reference.jsonl build/perf/batched.jsonl
```

Add `--strings-only` only for the documented extraction-only comparison. Add `--mixed` to both runs when comparing mixed-codec output. Explicit plugin paths can replace the load-order arguments, and `--detect-only` measures context decisions without full enumeration. Repeat measurements in fresh processes and again with warm data; record cache conditions separately. The comparator rejects changed inputs, corpus order, references, decisions and errors before printing speedups.
